# 延迟缓存优化实验

2026-09-17，目标为缩短 Thunder CTS-MoE 采样时间。实验使用原服务器 RTX 5090、4096 环境、24 个控制步/更新、4 个物理子步；环境、奖励、网络和 PPO 参数保持一致。

## 实现边界

`fast_delay.py` 复用服务器 Isaac Lab 2.3.2 的原始缓存状态、延迟抽样、参数校验与 reset。缓存容量改用已知的 Python 整数，reset 时记录需要重新填充的环境索引，compute 不再反复通过 GPU 标量查询容量和 reset 状态；advanced indexing 已返回独立张量，因此移除多余 clone。

四组执行器仍各自抽样 0–4 个物理步的延迟。同一执行器内位置、速度和力矩仍共享抽样延迟。首次填充、部分重置、历史不足时取最早可用值、环形指针与输出内存隔离均保持原语义。没有合并执行器或改电机模型。

接入是显式 `--fast-delay` 开关，默认关闭。没有修改服务器全局 Isaac Lab、原版 rsl_rl 或正式训练中的对象。实验代码在服务器独立 `delay_optimization` 目录。

## 验证

- 本地 buffer differential + wheel reward 回归：18 项通过。
- 服务器以 `ISAAC_BUFFER_SOURCE` 指向实际安装的 Isaac Lab 源码：13 项 CPU/CUDA differential 测试通过，包含部分 lag 修改。
- 真实执行器 GPU 测试：四组 × 17 环境 × 19 步输出逐值一致；CPU/CUDA RNG、reset、独立随机延迟、DCMotor 扭矩速度曲线、轮部 ±17 Nm 限幅通过。证据 `receipts/delay_actuator_parity.json`。
- Ruff 通过。

## 测量方法

单测为四组各三个缓冲区，每个缓冲区四关节，4096 环境、96 个物理步，6 次交替测量。服务器正式训练同时运行，因此该结果只表示组件级实验：中位数 0.543→0.099 秒，约 5.50 倍。不能乘到完整采样时间上。

完整 A/B 在同一个隔离训练进程中使用相同环形缓存，按 ABBAABBA 交替选择原始/优化 compute。正式 PID 在实验期间 SIGSTOP，脚本用 EXIT trap 和 timeout 保证正常退出/错误/超时后 SIGCONT，并单独核验恢复。测试权重全部丢弃，不会成为正式训练检查点。

首轮 `benchmark_delay4096` 仅采用上游无 CUDA 同步的计时，不能用作性能结论。`benchmark_delay4096_sync` 在采样结束及迭代结束显式同步 GPU，`wall_collect_seconds` / `wall_seconds` 为决策依据；4 轮热身，8 块 × 3 轮，各路径 12 个正式样本。随后单独采集 cProfile，避免 profiler 开销污染计时样本。

不能把 cProfile 中 `.item()` 的累计时间全部视为缓存自身可消除的运算：同步点会等待之前排队的 GPU 工作，删掉一个同步点可能只把等待移到后续 PhysX/奖励/观测读取处。

## 完整实测结果与决策

同步计时每种实现 12 个样本，中位数如下。阶段中位数不要求相加等于总时间中位数。

| 指标 | 原版 | 优化版 | 耗时减少 |
|---|---:|---:|---:|
| 采样，已同步 GPU | 5.346 秒 | 5.237 秒 | 2.04% |
| 返回计算与更新，已同步 GPU | 0.530 秒 | 0.513 秒 | 3.19% |
| 整轮，已同步 GPU | 5.878 秒 | 5.706 秒 | 2.93% |

本次没有修改更新阶段的代码，其差异说明实验仍存在负载/学习批次波动，不能把整轮 2.93% 全归因于缓存。此前 24 样本/路径的非同步诊断基本持平（采样只差约 0.09%），因此当前证据只支持小幅、尚未证明稳定的收益，不支持数倍整体提速。

随后独立采集每条路径 2 轮 cProfile：原版 `fetch_results` 累计 6.427 秒，约 3.21 秒/轮；优化版约 3.26 秒/轮。原版延迟 compute 约 0.313 秒/轮，优化后约 0.150 秒/轮。PhysX 推进/等待结果是当前主要的 CPU 端耗时位置；进一步区分 GPU 碰撞、求解及其他排队工作需要 GPU 时间线，不能仅靠 CPU profiler 断言底层原因。

决策：保留已验证的实验实现与显式开关，默认关闭；正式训练不重启、不恢复检查点、不启用该实验路径。正式 PID 12542 已由 T 状态恢复为 S/R，继续从原内存状态训练。采样优化的下一优先级是 PhysX GPU 时间线及碰撞/求解负载，而非继续将延迟缓存当作主要瓶颈。

证据：`receipts/delay_sync/summary.json`、`timings.jsonl`（前 28 行为 4 轮热身与 24 个正式样本，最后 4 行为 profiler 诊断，不纳入 summary）、两条路径的 `*_profile.txt`；正式恢复状态见 `receipts/delay_formal_resumed.json`。暂停期间跨越的正式迭代会出现计时离群点，不能用于重新计算正常速度。
