# Thunder CTS+MoE 起步、姿态和越障联合评估方案

版本：2026-09-21 / V13-evaluation-plan-1。目的：逐关节找出异常动作，并验证修复同时保留运动和越障能力。本文是评估合同，不修改训练奖励，不追加训练轮数，不代表实机放行。

## 1. 结论如何作出

必须分别回答四个问题，不能以总奖励或平均地形等级代替：

1. 起步是否仍发生异常下蹲、伸腿、回弹和速度超调？异常由哪一关节、何时、哪一级目标产生？
2. 完整25秒内是否持续保持正常运动，停止、反向、旋转和重新起步是否正常？
3. 楼梯、高台、坡面等能力是否保留，末端是否平稳恢复？
4. 力矩、转速、限位和接触是否符合当前仿真执行器合同？

记录四层结果：数据有效性、原300轮门控、姿态质量目标、随机稳健性。任何层不能以另一层高分抵消。原门控通过只表示允许讨论下一段实验，不表示所有质量目标已达标。

当前 V13 已完成新增300轮，总完成45,011轮。九地形评估在保存轨迹时发生磁盘空间不足，尚未形成有效完整报告。残留NPZ及未完成案例不得当作通过结果。先恢复评估存储，再执行原定332+100例；不重跑训练。

## 4. 每个关节都评估，不只给整体RMS

腿关节共12个：左前、右前、左后、右后各自的髋、大腿、小腿。4个轮关节另表，轮子不以累计旋转角相对默认角评价站姿。

定义 `e_j(t)=q_actual,j(t)-q_default,j`。

- 瞬时整体RMS：`sqrt(sum_j(e_j(t)^2)/12)`；其峰值仍可能掩盖单关节异常。
- 单关节时间RMS：`sqrt(mean_t(e_j(t)^2))`；每个关节分别算，不混入其他关节。
- 每关节同时报告带符号均值、平均绝对偏差、绝对偏差P95、最大绝对偏差、峰值正负方向和发生时刻。
- 实际角对目标的跟踪误差与“偏离默认姿态”分开：目标本身错误时，跟踪准确也可能是坏动作。

| 逐关节指标 | 用途与约束 |
|---|---|
| 原始请求角、限位/变化率限制后目标、实际角 | 三条曲线同轴，默认角及软/硬限位同图 |
| 实际偏差峰值及当时请求/目标 | 同一时刻对照，禁止拼接三个不同时间的峰值解释因果 |
| 请求/目标单步变化、变化率 | 包含实际重置角到第一步目标；也统计每次命令切换 |
| 实际对目标误差 | 当前目标在延迟前，只能作响应诊断；真正执行目标误差需补延迟后目标采集 |
| 力矩、速度峰值及发生时间 | 与下蹲、起跳、触地、限位阶段对齐 |
| 硬限位超量、软限位附近停留 | 区分真实越界和长期贴边卡住；需导出逐关节限位 |
| 饱和比例、连续饱和时间 | 区分需求过大、力矩被裁剪与姿态失效；连续时间需200Hz事件记录 |

已有逐关节脚本可输出RMS、MAE、P95、峰值、同刻请求/目标、目标变化、力矩/转速峰值和硬限位超量。每关节软限位停留、延迟后目标、200Hz连续事件为补充采集项，不能从现有50Hz曲线假装已算出。

### 时间窗口和事件对齐

现有窗口：给运动命令后0–1秒、0–2秒、2–5秒、完整有效轨迹、末1秒；完整平地增加回合5–15秒、15–25秒。

新增事件窗口：reset前后首100ms；每次命令切换前0.2秒至后2秒；楼梯末端前1秒至后3秒；高台接近、首次前轮上台、全身上台、停车后各独立对齐。必须保存“回合时间”和“距事件时间”，避免把2秒等待计入起步指标。

失败后的reset帧不参与原回合统计。提前失败的窗口记为不完整，并计入失败；不能把剩余短片段当成完整25秒。每个窗口给样本数、有效时长、完整性标记。

## 5. 平地姿态、跟踪和命令切换

完整平地必须检查：机身相对地面高度、roll/pitch、世界竖直速度、四轮支撑、机身触地、各关节姿态、速度跟踪。高度目标0.46m只适用于真实平地参考；不能把坡面/高台边缘不正确的地面射线当作机身下蹲。

速度误差分别报告vx、vy、yaw的带符号偏差、MAE、P95、峰值，以及XY向量误差。另报告超调、到达并连续保持误差带0.5秒的整定时间、停止后的残余速度和位移。短时“某一点到达命令”不等于稳定跟踪。

纯旋转单独报告XY漂移；直线单独报告侧偏和航向变化；转弯/斜向按命令轨迹评估，不能用固定直线偏差误判。原主评估不加航向反馈；若另测航向控制器，单独列为系统表现。

## 6. 执行器与接触：不能只看有没有终止

当前仿真合同 `rs0402_transient_v4`：腿120Nm、轮17Nm力矩上限；名义速度腿15rad/s、轮30rad/s。目标变化率12rad/s，即20ms一步最多0.24rad；软限位仍独立生效。

当前超速终止：超过名义速度1.02倍持续至少0.06秒，或超过1.5倍即时终止；腿对应15.3/22.5rad/s，轮30.6/45rad/s。力矩超上限0.001Nm、实际角超硬限位0.01rad也属于违约。**这些是现行仿真判据，短时未终止不意味着没有超速，也不等于实机安全认证。** 35/6Nm负载参考不是已确认的连续额定力矩。

12腿+4轮逐个输出：峰值、P95、超过名义转速总时长/最长连续时长、扭矩裁剪时间、角限位停留、违约原因。200Hz逐物理步用于瞬态；50Hz整步峰值可以保留最高值，但不能还原峰值持续时间或精确冲量。

接触需补完整三轴接触力、接触对象/位置、轮子接地状态、机身触地事件。现有轮接触力范数不足以判断切向打滑或精确支撑。轮速减机身vx也不能直接当陡坡打滑率，需接触切平面速度和有效滚动半径。

各类输出尝试数、完成数、物理失败数、超时数、侧偏数、失稳数以及交叉关系；失败原因可多标签，另列第一个触发原因，避免总数误相加。训练地形平均等级、等级分布只作为训练覆盖证据。

### 楼梯最后一步

必须导出楼梯末端几何位置与完整机身/轮子越界信息。取消该专项测试的4m提前结束，在全身上平台后继续至少3秒；再单独测试停车2秒。测试场地不够长时判协议不足，不能用撞边界后的姿态统计。

阶段由几何和接触确定：接近→爬/下阶→前轮到平台→后轮及机身全部离开边缘→平台运动→停车。不得因“姿态已经恢复”倒推“已上平台”，否则会漏掉恢复过急的问题。

重点曲线：pitch及变化率、世界竖直速度、机身高度、轮接触、腿请求/目标/实际、力矩。全身越界后2秒内应向平地质量带恢复；攀爬未完成前不套用默认姿态窄带。若末端竖直速度>0.50m/s，标为待解释异常；须结合接触、空中时间和后续稳定性，不把这个单值当作所有台阶的物理失败阈值。

### 高台

当前7个高度仍作为历史固定回归；另补1.00m（第17档）以支撑“可爬1米”结论。0.60/0.90/1.00/1.20m是重点。每档0.3/0.6/0.9m/s；不以低台阶高成功率代替1.2m结果。

分别计数：前轮上台、全身越过、稳定登顶。全身越过基于已有碰撞几何与轮子支撑逻辑；登顶停车采用原程序外部清零速度命令，报告必须注明。

原稳定条件包括四轮支撑、全身越过、倾角<15°、XY速度<0.15m/s、角速度范数<0.3rad/s等，连续2秒；姿态条件按运行配置记录。现有支撑逻辑使用轮子垂直接触力>5N及轮底高度接近台面，不能用现有记录的力范数冒充垂直力重算。

前进命令≥0.2m/s而2秒推进<0.05m标为“停滞诊断”，需检查后腿、限位和支撑，不新增自动终止。仅前轮上台不算成功，偶发一次登顶不算稳定掌握。

## 8. 现行300轮门槛：保持原样

来源 `gates.py`，本轮调用 `final=False`，不能把未来final门槛当成现在正在执行的标准。

- 四项：九地形学生/教师，完整平地学生/教师，必须分别通过。
- 各非平地通过数不减少、物理失败数不增加；楼梯直行4m通过数不减少；高台原来成功的每个高度/速度案例必须保留。
- 平地通过数不减少、物理失败不增加。
- 直接前进起步RMS：若基线>0.25rad，候选必须低于基线80%；否则必须<0.25rad。完整平地两种前进起步方式也检查。
- 每个平地案例末段XY误差不超过`max(0.15,旧值)+0.02`；yaw不超过`max(0.20,旧值)+0.02`。
- 完整平地保留旧策略已完成的25秒案例，不新增物理失败；每案例全程RMS峰值不超过`max(0.35,旧值)+0.02`；两种前进案例全程RMS必须<0.35rad且完成25秒。

局限：总通过数可能掩盖“原成功案例失败、另一个补上”的交换。下一层质量报告额外逐案例展示成功→失败清单，不能只报总数；目前只有高台在原门控中强制逐成功案例保留。

## 9. 随机稳健性与速度扫描（后续有限评估，尚未执行）

先完成确定性诊断和当前门控，再冻结可复现种子列表，逐因素加入观测噪声、初态扰动、执行延迟和推扰。范围取实际训练配置并随报告保存；不临时杜撰随机范围。最后加联合扰动。每个策略共享同一组抽样，比较成对差值和退化案例。

速度扫描先覆盖已训练范围：前/后0.2、0.6、1.2m/s，左右0.2、0.4、0.5m/s，纯转0.3、0.6、0.8rad/s。更高速必须从运行配置确认范围，作为扩展能力另列；不因高速度大姿态与低速窄带不同而混在一起。

随机阶段先每关键条件20个独立种子查失效模式；只能叫探索。准备宣称稳定能力时，预先指定关键条件，每条件另用100个未参与调整的种子。报告成功数/100及Wilson双侧95%区间，不能只报百分比。工程目标为区间下界≥90%（100次中至少96次成功）；此为逐条件结论，不声称多个条件同时有95%置信保证。多环境同种子/同地图不能假装独立样本。

关键条件至少覆盖：全向直接起步、停止再启动、上/下楼梯末端、波浪高等级、45°上/下坡、0.6/0.9/1.0/1.2m高台。先筛查再明确最终验收条件清单，冻结后不删除难案例。100次验收集不参与调参；若继续调参，下一候选另用保留集。

## 10. 问题定位与下一次修改原则

按时间先后追踪：命令→观测/历史→策略原始请求→软限位/变化率目标→延迟后执行目标→力矩→实际关节→支撑/机身运动。

- 原始请求先突变：检查策略对重置/命令的响应、学生和教师差异、MoE门控及专家输出；不能直接认定是电机不够。
- 请求正常但目标突变：检查reset、限位、延迟缓存和动作处理。
- 目标正常但实际异常：检查接触、PD、饱和、初始化与动力学。
- 实际关节先大偏移再碰障：检查默认起步行为；碰障后才大偏移须按攀爬阶段判断是否必要。
- 表现改变只出现在命令渐变组：说明输入平滑帮助，不能宣称直接起步已修复。

如需检验原因，一次只改变一个因素，在相同检查点/种子/场地上比较。奖励账本、锚定/蒸馏/PPO梯度冲突为需要时的诊断；总奖励或梯度相关性不直接证明因果。失败后停止候选长训，准备有限对照；不自动加大奖励、锚定权重或缩小所有地形动作范围。

## 11. 交付物与执行顺序

第一批：恢复存储，完成432例，不增加优化器更新；取回原始轨迹、manifest、四项gate结果、九地形通过表、12腿+4轮逐关节CSV/JSON及图。当前逐关节统计已接入analyze，新增质量目标和专项末段协议尚未全部实现。

第二批：补延迟后目标、200Hz事件和几何阶段采集，完成全回合切换/楼梯末端/高台1m专项。先验证采集时间对齐和无训练更新，再执行。不能在缺少传感字段时用估算替代验收证据。

第三批：确定性层满足目标后执行随机/噪声/速度扫描；随机组预算和案例清单单独冻结。未完成该层时只能说明固定案例表现。

每批交付：

1. 九地形完整计数表，学生/教师分开，物理失败/超时/姿态异常分开。
2. 逐关节表：12行腿表、4行轮表；列最差方向/地形/案例ID/时刻，附是否完整。
3. 同条件12关节请求/目标/实际时程，机身高度/姿态/速度/接触联合图，0–2秒放大与完整25秒并列。
4. 楼梯末端和高台接近/攀爬/登顶事件图，标出命令切换和支撑变化。
5. 预定义每组最差、近中位数和最佳案例视频，失败案例不能缺席；注明选择规则。
6. 结论表：已改善、仍未达标、无法判断；下一项单因素实验及有限预算。

任何训练续接须另有明确依据；本方案不自动恢复训练，不部署实机。评估异常与策略行为失败分开记录。
