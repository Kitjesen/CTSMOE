# 默认站姿起步、正常接近与攀爬验收

用户于2026-09-21明确要求：必须能够在默认姿态基础上爬高台和走楼梯，并覆盖其余全部地形。不能将恢复旧策略的大幅下蹲、趴伏或起步跳动当作成功目标。

## 目标行为

1. 从Thunder配置的默认关节角、正常机身高度和静止状态起步。
2. 无障碍起步与接近阶段保持正常站姿和速度跟踪，不因收到速度命令就深蹲、趴伏或跳跃。
3. 遇到实际障碍后，允许完成任务所需的抬腿、屈伸和机身俯仰；用逐关节请求/目标/实际角及障碍距离判断动作是否与攀爬有关。
4. 全身越过障碍后恢复正常运动姿态；零命令时回到默认站姿附近并稳定停车。

默认站姿是初始化和常态姿态目标。本文件不新增“攀爬全程固定所有关节角”的硬约束，不凭口头要求宣布1.2m目标已经可达。

## 验收修正

- “从默认角初始化”只证明初始条件，不能替代对收到指令后整个接近阶段的姿态检查。
- 高台完成率与运动质量分别记录，两者都通过才接受。旧43,106轮策略的9/9只作为任务完成能力参考，不能当作最终合格策略。
- 不将旧高台完整动作直接当成必须保留的蒸馏目标；其中不符合姿态要求的准备动作不能盲目复制。若使用历史示范，需先按运动阶段和姿态质量筛选。
- 相同命令分别测试平地、上下楼梯、上下坡、波浪、粗糙坡、障碍块和高台，比较动作是否真正由障碍条件触发，而不是通用的坏起步。
- 记录初始默认角、障碍相对位置/轮缘距离、机身相对支撑面高度、速度、机身俯仰、足轮支撑及逐关节请求/目标/实际角。攀爬阶段不能仅以偏离默认角判失败；也不能仅因攀上就忽略姿态问题。
- 现有213例固定评估的通过数仍按原规则保留，不能事后改称已满足本验收。新增阶段验收须另行实现和验证，并给出依据明确的阈值。

## 当前运行边界

V7千轮实验按用户既定要求继续，不在运行中暗改奖励或执行器限制。千轮后的评估结论必须同时说明任务完成情况和上述姿态质量，不能只报告高台/楼梯通过数。阶段验收和符合该目标的新训练设计尚不能以本记录代替实现。

## 跨地形起步证据

冻结策略九地形数据的分析见 `all_scene_v6/common_startup.json` 和 `common_startup_joint_map.png`。同为立即给0.6 m/s的名义条件，源学生策略在平地、上下楼梯、上下坡及障碍块的首秒实际腿关节偏差RMS约0.44–0.46 rad；下楼、上下坡和障碍块的请求角偏差时程与平地的余弦相似度约0.996–0.999。该结果支持存在跨地形重复起步模式，而不只属于高台准备动作。相似性本身不能证明每个动作都错误，仍需结合障碍位置和支撑状态。

V6将多种地形上的初始姿态偏差一起压小，但高台9例均未通过。因此后续评价需要同时检查正常起步和遇障后的动作切换，不能把姿态偏差越小视为全阶段越好，也不能直接复制旧策略的整段动作。

新增诊断记录扫描起伏及有效性、四轮离地间隙与地面接触力、高台前缘距离和登顶停车状态。它们是阶段分析的测量依据；尚未宣称已实现适用于九地形的自动阶段判定和合格阈值。
