# V12 起步前两秒：冻结策略因果诊断

2026-09-21。训练仍停在完成45,011轮，V12未获行为门控通过。此次没有训练、没有修改奖励、没有实机部署。

## 结论

存在两个需要分开处理的问题：

1. **确定的显式 reset 目标初始化错误。** Robot 被放回默认关节角，但 `joint_pos_target` 仍为绝对角度0。`env.reset()` 随后调用 `scene.write_data_to_sim()`，把0填入刚清空的执行器延迟缓冲。默认小腿角为±1.96rad，前10ms却在追0rad，造成±120N·m冲击，随后反向制动。
2. **独立存在的策略起步响应缺陷。** 消除上述缓存错误后，直接给0.6m/s仍有约0.492rad首秒姿态偏差。该网络在“默认姿态、历史动作0、立即给纯前进”的输入下，第一批输出已经偏大，后续动作反馈继续维持大偏姿。仅降低变化率没有修复；改变命令最初几十毫秒的切入路径明显改变了后续响应。

两批共32个固定诊断案例，每例8秒（各400控制步），共800批量控制步、0优化器更新。V6/V9/V12输入检查点和模型状态哈希未变。使用同一平地、默认初态、无噪声/推扰、固定10ms执行器延迟（明确变更延迟的对照除外）。这不是随机成功率，也不代表全向、25秒、楼梯/高台已验收。

## 为什么策略第一批输出就大

### 默认站姿只是动作坐标的偏置，不是网络必然遵守的动作

腿原始请求为 `default_q + 0.25 * policy_action`。actor末层为线性输出，没有“收到运动命令后先保持默认姿态”的硬规则。网络通过训练决定偏移量。

在完全相同的reset观测上，仅改变速度命令，冻结V12网络的原始请求偏移RMS为：

- vx=0：0.1148rad，最大单关节0.2187rad；
- vx=0.3：0.2414rad，最大0.4321rad；
- vx=0.6：0.3047rad，最大0.5927rad。

这发生在任何物理步之前，故第一批大请求不是由之后的地面反力才产生。实际guard后动作仍受soft limit和slew约束；这里不是说以上所有原请求都直接执行了。

### 动作历史参与了后续输出

`ActionManagerGo2`存储未经过关节位置/slew处理的action；观测中的`last_action`读取这一路。实际执行则经过缩放、位置限制、slew和delay。因此输入里的“上一步请求”与实际执行目标可以相差很大。该设计未证明是接口错误，但这次需要同时检查两条信号，不能只看action或actual其中之一。

在录制的0.10s状态上，离线仅把single/history中的动作输入置0，下一次原始请求RMS从0.4771降到0.2210rad；0.50s为0.4757降到0.2093。物理状态和速度命令保持原值。这支持网络对先前动作有明显依赖，与“大动作输入后继续生成大动作”的诊断相符。

这些是**离线输入反事实**，不等于真实闭环行为验收；不能据此在部署中把last_action直接清零。

### 不能继续解释为“必须积累两秒历史”

实际历史有10帧，每个term按其自身的历史次序拼接；reset后首次append会重复首个观测，并非留着上一回合历史或把整个530维输入置零。将过去命令设为0只小幅改善；只经历20–40ms的零命令动作后再前进，效果就显著不同。所以最关键的是起步路径和反馈状态，不能把原因简化成“历史帧不够长”。

教师首秒RMS同样约0.463，因此问题也不是学生MoE独有。该组初始观测和输入反事实中8个gate权重约0.122–0.131，没有快速切换专家的证据；不把震动归因于专家切换。

## 动作变化率为什么没挡住

12rad/s在20ms控制周期内允许0.24rad变化。限幅约束的是相邻目标的变化，不限制最终目标偏离默认姿态有多大。

3rad/s对照虽然限制到每步0.06rad，前2秒目标仍可偏离默认约0.999rad（原流程约1.023rad），最终仍明显下蹲。6rad/s甚至比12rad/s首秒峰值稍大。因此不能把“继续降低全局slew”作为已证明有效的修复，也不能由这几个平地固定case确定楼梯/高台应该使用哪一个rate。

## reset错误的源码与适用范围

- `runtime_manager_based_env.py:371–376`：显式reset先`_reset_idx`，再`scene.write_data_to_sim`和`sim.forward`。
- `runtime_manager_based_rl_env.py:358–372`：scene/actuator reset先清buffer，reset event改实际关节状态，随后重置action manager；没有同步robot的绝对position target。
- `runtime_circular_buffer.py:137–141`：第一次append将该数据填满此环境的全部历史。
- `runtime_actuator_pd.py:363–367`：delay后的目标送入PD。
- `results_r1/physics.npz`：实际抓到reset阶段及第一个控制步前两次计算使用0rad小腿目标，随后切回约−2.054rad，伴随力矩反转。

普通`ManagerBasedRLEnv.step()`内部的自然回合reset没有同一段write/forward，见`runtime_manager_based_rl_env.py:218–238`。所以本报告确认的是**显式reset/首回合评估的这条初始化链**，没有声称训练中的每次自然reset都发生同样的零目标脉冲。

在隔离诊断中，`_reset_idx`返回后、`write_data_to_sim`之前，把位置目标同步成实际reset角度，速度/力矩前馈目标清0，消除了这个虚假的0rad目标。第一控制步腿峰由120降到约32N·m（仅reset同步），但后续直接起步仍会因策略动作再到120。因此修复初始化是必要的独立工程修复，不是完整的姿态学习修复。

## 已准备的修复及后续顺序

1. `reset_targets_candidate.py`使用正式articulation target setter实现上述同步，不改物理状态、不操作私有delay缓存。3个回归测试通过，覆盖部分环境reset、二次reset新姿态、空集合/错误形状；等价调用顺序已在r2 GPU诊断验证。尚未接入正式train/evaluator。
2. 准备在相同完整25秒、普通5秒重采样下验证命令入口的0.2秒渐变。它是输入路径修正，不是把运动片段缩成0.2秒，也不是已经训练出了新策略。需要全向、随机初态/噪声、速度扫描以及九地形回归后才能成为正式行为。
3. 训练侧明确加入纯前后/侧向/旋转起步覆盖，核实参考样本实际进入更新。把“直接阶跃起步也要正常”保留为独立验收，不能只用渐变测试掩盖原始策略缺陷。保留V6参考、V9越障来源和全部检查点。
4. 本轮不改变任何奖励/锚定系数，不自动开启700轮，不把全局slew降到3或6。新的有限训练须先完成这些入口修复的集成与功能验证，并沿用行为门控。
