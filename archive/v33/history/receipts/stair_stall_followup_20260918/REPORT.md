# 低速高台阶停滞：原始动作核验与新策略复测

2026-09-18。本轮增加只读诊断，正式训练未停止、未改参数；没有修改实机控制。

## 结论

旧样本不是简单的“电机峰值不够”。此前“策略维持不动”的表述遗漏了目标限幅：网络持续请求左后小腿2.950–2.978 rad，被新增动作保护持续裁剪为2.826 rad。旧策略在改变后的动作执行规则下陷入不利支撑姿态，未自行改变动作脱离。目标裁剪的存在已直接测得，但本轮没有位置范围消融，不能称它是唯一根因。

新21,001轮检查点在相同rs0402_peak_v2约束和相同固定测试下，约25cm上楼、0.3m/s由1/3提高为3/3，约15秒通过4米出口。证明这个约束下存在可行策略，也表明续训已有适应效果；不证明任意初态或扰动下都能成功。

## 旧样本为何“没有用满120”

原始请求采集于位置动作缩放后、软边界和变化率投影之前。旧19,001检查点全部162个案例的既有结果与上一轮逐项完全一致，新增观测未改变轨迹。

案例126最后5秒：

| 左后小腿相关量 | 测量 |
| --- | ---: |
| 网络请求目标 | 2.950–2.978 rad，均值2.968 |
| 动作软边界上限 | 2.826 rad |
| 实际施加的位置目标 | 全部251个采样均为2.826 rad |
| 实际关节角均值 | 2.782 rad |
| 请求超软边界的采样占比 | 100% |
| 左后小腿实际扭矩均值 | 5.25 N·m |
| 全腿峰值／全轮峰值 | 51.64／6.31 N·m |
| 机身前进量 | −4.3 mm |

120 N·m是扭矩上限，不是检测到障碍后自动施加的力量。位置PD按目标与实际角度之差生成扭矩；裁剪后角差约0.044 rad，Kp120对应约5.3 N·m的位置项，另有阻尼、延迟与电机模型。提高峰值上限不会自动增大这个位置误差，也不会自动产生换支撑动作。

2.826是URDF机械范围约±3.14 rad的90%软范围。该样本原始目标仍在机械范围内，但被更窄的动作软范围裁剪。不能混淆“目标超软范围”“实际关节超机械范围”和“扭矩超限”。本轮未放宽任何边界。

此前记录显示前轮比后轮高约0.61米、右前轮连续无接触，后轮几乎原地停留。本次奖励记录还显示腿部非期望接触惩罚持续为−2（按大腿/小腿接触历史计数），与不利支撑相符；没有记录每个非轮接触体的完整力/接触点，不能进一步断言哪个部位精确顶住哪一级台阶。

## 奖励与学习机制的解释边界

实际代码速度项为2×exp(−||v_cmd−v||²/0.5²)。0.3m/s命令、完全静止且横向速度为零时，仍得1.395，约满分的70%；这个旧样本停滞窗口实测1.392。4米条件用于课程升降级，未另设持续停滞惩罚或脱困奖励，25秒超时还按上游PPO逻辑bootstrap。

但是该窗口的**总奖励率实测为−0.483**，含非期望腿部接触−2、力矩平方−0.489、负载−0.154等。因此不能说“总奖励在鼓励卡住”或“已经证明停着比前进划算”。低速速度项区分度有限是可能加重问题的因素，不是本次证实的唯一原因。新策略在相同奖励下已经能完成这些样本，没有证据要求此刻立即重写整套奖励。

教师获得真实线速度、接触、高度扫描等特权状态；学生只有10帧本体状态历史。上游CTS中共享actor使用教师和学生轨迹做PPO，学生MoE编码器用学生访问状态上的教师latent MSE及专家均衡损失更新。不存在每次卡住就显式接管或标注“抬后腿”的逻辑。平均蒸馏损失小，也不保证少数高台阶状态动作完全一致。这里只能说明可能的学习瓶颈，尚无单因素感知消融。

新策略这些成功样本腿峰值仍到120 N·m、部分轮峰值17 N·m，实际机械角度超限为零，没有触发执行器违规终止；不能据此声称持续负载/热安全已验证。剩余上楼失败在L9、0.9m/s，1.62秒时右前轮峰值46.758rad/s，触发30.6阈值。高速接触冲击与波浪仍有未解决问题。

新检查点21,001包含恢复峰值后294次更新；19,001旧检查点形成于动作保护之前。两检查点之间还经历了v1受限训练，不能把全部改善归因于单一权重修改。
