# 后续混合楼梯：独立、限量、默认停用

本目录是 V24 单因素修髋之后的独立编排。**当前 `SOURCE_REVIEW.json` 为 HOLD，不能运行 `prepare.py` 或训练。** V24 `orchestration/driver.py` 不调用本目录。只有 V24 的 16+984 修髋训练和九地形、25 秒平地、楼梯末端、15 厘米连续阶梯的源/候选配对评估全部完成，审阅轨迹并明确选定源之后，才可以启动。此目录没有自动部署步骤。

可选源只有 V24 的原源检查点或完成 1000 更新的修髋候选；不能按“最新检查点”自动选。将 `SOURCE_REVIEW.json` 的 `decision` 改为 `eligible_for_bounded_mixed_stair_test`，填写 `selected_source` (`v24_original` 或 `v24_hip_candidate`)、对应绝对 `source_path`、SHA-256、`source_completed_updates`，以及 `orchestration/ASSESSMENT_PROOF.json`、`BEHAVIOR_COMPARISON.json` 的 SHA-256。`behavior_findings` 至少写明髋实际角及持续内夹、原九地形、平地姿态、15 厘米路线与平台停车、物理终止和关节扭矩/转速的判断依据。两者训练历史不同，选原源不会退还 V24 已花的 1000 更新。`real_robot_release` 必须保持 `false`。

在独立远端目录完整复制 `v24_integrated_20260923` 后，且 GPU 空闲时手动执行：

```sh
python mixed_orchestration/prepare.py
python mixed_orchestration/driver.py
```

`prepare.py` 只冻结代码、审阅决定、源哈希与 V24 全套评估证据。`driver.py` 是一次性入口：先在真实 Isaac 中运行 4096 环境、3000 控制步、零优化器更新的混合楼梯预飞，独立核验模型、PPO/学生优化器、地形恢复、首次直行/Yaw/侧移组、四轮地形接触力、URDF 碰撞包络与机身壳体。缺少接触见证时停止。之后只运行 **16 + 484 = 500** 次优化更新，先保存再恢复双优化器和混合课程状态，精确停在目标轮次。原从 31831 起总预算 10000；V24 后剩 5000，本阶段最多花 500，剩 4500。失败不自动重试、续跑或增加预算。

评估用相同 V23 协议配对源/候选的学生和教师，覆盖原九地形 332 例、平地 80 例、楼梯末端 96 例和 15 厘米阶梯 96 例。新增 `signed_mixed_stairs` 128 例：上/下楼、等级 0/9、前进加 Yaw 或侧移、正负脉冲、0.45/0.65 m/s，四种策略完全配对。记录两段脉冲的指令和实际同向响应、四轮平台连续 2 秒支撑、物理违例及关节/接触时程。每段指令必须与案例的方向、速度及时间窗一致；实际同向响应至少达到指令幅度的 40%，平均绝对误差不超过幅度的 75%。固定的 V23 `hip_metrics.py` 从签名时程生成逐例、逐关节证据。终点支撑使用经 URDF 验证的保守轮碰撞包络和机身壳体、四轮地形过滤接触力；轮下 XY 是几何推断，不能称为实测触点。候选签名门槛是 64 个学生/教师案例均有两段同向响应、四轮平台 2 秒支撑且无物理违例。未通过仍保存完整结果并标记待审，不宣称实机可用。

所有结果是固定仿真案例，不能当随机成功率。仿真资产关闭自碰撞；仍需实机故障码、关节原始请求/目标/实际角、扭矩时程和实际部署 ONNX 输入输出/关节符号核对。本阶段不放行实机。
