# Thunder 下台阶三次失力专项资料

本目录保存用户确认的三次实机下台阶/下马路牙子失力事件，依时间顺序编号。主分析见 [`三次事件专项分析.md`](三次事件专项分析.md)，可筛选的摘要见 [`事件索引.csv`](事件索引.csv)。

用户估计晚上实物楼梯约 20 cm 高、25 cm 踏步深，稍后拟实测；该估计已写入主分析，不当作精确地形记录。

- `raw/`：实机应用、syslog、内核日志的只读采集快照。原始日志可能含 NUL 填充和跨启动拼接半行；不要按字符串排序重建事件时间。
- `events/`：各事件前后的逐帧 CSV 和保留原文的 TRACE10 摘录。四腿顺序始终为 FR、FL、RR、RL；Calf 对应电机编号 2、5、8、11。
- `profiles/`：当前实机上的两个相关 profile 副本。01 的参数由当时 TRACE10 `calfKp=95`、启动日志及 profile 相互印证；不能仅凭现在文件内容证明历史文件从未被编辑。
- `reference/`：本地 MuJoCo 假设、服务端固定评估和一份**未证实为当前实机烧录版本**的电源板源码，用于区分实证与假设。
- `MANIFEST.json`：证据文件大小、SHA-256 和采集来源。`raw/` 对 `.codex_stage` 保留副本使用 NTFS 硬链接或字节复制，内容按哈希核对；互为独立目录项。

可在本目录运行 `python -X utf8 verify_archive.py`，核验全部证据哈希和三个逐帧 CSV 的行数。

设备系统使用 PDT，但断电重启后的启动段多次先恢复旧时钟、后同步网络时间。01、03 事件只可靠地保留设备原时间及启动顺序；02 事件发生在已校时的启动段，约为北京时间 21:18:30。三个事件不能直接靠设备日志时间做跨启动间隔计算。

本资料为只读采集和离线分析，没有对实机发送运动或使能指令，也没有修改机器人服务或控制参数。
