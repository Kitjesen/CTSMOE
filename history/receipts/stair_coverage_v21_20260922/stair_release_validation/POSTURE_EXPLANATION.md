# 12腿关节相对默认姿态的偏差解释

本次仅复核已保存的34823楼梯轨迹和冻结训练配置，没有训练更新。

指标为 `sqrt(mean((q_actual - q_default)^2))`，覆盖12个腿关节，不含4个轮关节。它衡量相对固定站姿的偏离；跟踪误差则应另算 `q_actual-q_target`。指标不能单独判断一次攀爬动作是否合理，也不表示12个关节都偏离同样角度。

## 两个0.6m/s、9级、立即给速、干净观测的完整案例

|阶段|上楼case28|下楼case64|
|---|---:|---:|
|首1秒RMS峰值|0.05667rad|0.05699rad|
|回合内RMS峰值|0.65126rad @4.84s|0.50732rad @3.32s|
|全身进入平台时间|6.62s|7.32s|
|最后0.5秒RMS均值|0.06596rad|0.09168rad|
|峰值时目标相对默认姿态RMS|0.62072rad|0.51061rad|

大幅偏离主要集中在台阶段，不能用这两个样本的台阶峰值推断整段平地起步均已退化。必要的跨阶屈伸会增大此指标；现有结果也没有证明全部大幅姿态都是必要动作。

## 上楼4.84s峰值逐关节证据

以下都是相对默认角的偏移，不是关节绝对角。

|关节|原始请求|限制后目标|实际偏移|实际减目标|
|---|---:|---:|---:|---:|
|左后大腿|−1.20756|−1.20756|−1.21030|−0.00274|
|左前小腿|+0.89442|+0.89442|+1.08503|+0.19062|
|右后小腿|+0.70505|+0.70505|+0.98456|+0.27950|
|左后小腿|+1.08716|+0.86600|+0.84808|−0.01792|

这4项合计占该帧总平方偏差约85.1%。左后大腿实际约偏69.3°，且紧跟策略目标，说明主要来源是策略要求的大姿态。两个小腿同时存在实际角相对当前目标的偏移；仅凭同一帧不能把它进一步归因为PD参数、惯性或接触，需看相位/延迟/力矩过程。

同帧左后髋原始请求偏移−3.18175rad，被截成−0.169rad，实际偏移−0.13715rad；右后髋请求+1.62432rad，被截成+0.169rad，实际+0.19256rad。原始请求的大数值没有直接成为同等幅度的实际关节位移，但持续大请求及限位依赖需要单独约束和验收。

## 训练设计为何允许这种动作

远端冻结`stair_coverage_v21/code/phase_pose.py`和真实预飞FINALIZED.settings.phase_pose确认：正常阶段两项额外实际角L1系数均−0.20，攀爬由几何phase weight抑制到可为0。由此，大腿/小腿默认角L1有效系数可从−0.21回到原版−0.01；髋从−0.25回到−0.05。基础项仍存在，不能说攀爬完全没有姿态惩罚。这些是训练目标；零更新评估时不计算学习梯度。

动作后处理限制机械角度范围和目标变化率12rad/s（20ms一次最多0.24rad），并没有把每个腿关节限制在默认角附近。允许较大的腿部活动范围本身并不保证策略选择最稳妥的姿态。

因此，数据已确定大偏移主要由目标姿态驱动，代码显示攀爬阶段的额外姿态约束明显减弱。这是需要审查的设计薄弱处。尚未通过单因素续训对照证明它是唯一根因，也没有完成低偏移攀爬轨迹的可行性比较。

原始逐关节值见`POSTURE_PHASE_AUDIT.json`；现有12关节图及原始请求/限制目标/实际时程保留。建议下一项有对照的修复聚焦攀爬阶段各关节合理活动范围、髋越限请求与平台恢复，并同时复测实际通过能力，避免仅把整体RMS压低就判成功。
