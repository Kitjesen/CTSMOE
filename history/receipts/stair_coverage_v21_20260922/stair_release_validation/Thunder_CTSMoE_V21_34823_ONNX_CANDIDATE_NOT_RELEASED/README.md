## 接口

ONNX opset 17，float32，两个输入：

| 名称 | 单机器人形状 | 内容 |
|---|---|---|
| `history` | `[1,530]` | 六类观测各自10帧历史，按类别拼接，每类内部旧帧在前 |
| `single_obs` | `[1,53]` | 当前帧观测 |
| 输出 `actions` | `[1,16]` | 12腿位置动作＋4轮速度动作，均为未做物理后处理的网络动作 |

模型没有内部历史状态。不能把单帧53维、既有平地55维输入，或者按整帧直接展开的530维输入替代本接口。它也不直接输出电机扭矩。

单帧依次为：机身坐标角速度3维×0.25；机身坐标投影重力3维；`vx,vy,wz`命令3维；12腿实际角减默认角；16关节速度×0.05；上一步16维原始网络动作。各项先截到[-100,100]再缩放。`actor_normalizer`和`single_normalizer`均为Identity。单位是rad、rad/s、m/s，竖直站立重力为[0,0,-1]。学生不需要教师的187维地形扫描输入。

历史块长度为`30,30,30,120,160,160`，每块时间从旧到新。重置后以第一次有效观测填满10帧。每20ms更新一次历史和策略。`reference_io.py`提供实测对齐的参考实现；模型推理示例：

```python
session.run(['actions'], {'history': history, 'single_obs': single_obs})
```

## 关节顺序和输出处理

策略顺序：右前FR、左前FL、右后RR、左后RL，每条腿依次hip/thigh/calf；最后四轮依次FR/FL/RR/RL。必须按名称映射到硬件，不能采用仿真物理数组的顺序。

策略顺序默认腿角：

```
FR [-0.20, -0.93, +1.96]
FL [+0.20, +0.93, -1.96]
RR [+0.20, +0.93, -1.96]
RL [-0.20, -0.93, +1.96]
```

腿原始目标=`默认角+0.25*action[:12]`，然后软限位和12rad/s目标变化率约束，20ms每次最多0.24rad。目标状态在reset时同步到实测q。轮速度目标=`5*action[12:]`，限幅±30rad/s。策略本身没有全局动作clip；观测中的last_action是原始动作，不是限幅后的物理角度。

源仿真腿PD为Kp=120、Kd=8，轮为Kp=0、Kd=1；力矩峰值腿120Nm、轮17Nm。详见`runtime_contract.json`的确切软限位和物理顺序。轮角位置无界，在标准JSON中用null表示；腿限位全部为有限数。

ONNX只包含策略网络。观测构造、历史缓存、关节映射、目标限位、控制器、时序、急停与电机保护由接入程序负责。现有仿真允许部分短时实际转速超过名义值，因此“没有仿真终止”不等于实机转速始终在上限内。

## 验证边界

144例涵盖上下楼、3/6/9级、0.3/0.6/1.2m/s、立即给速/先站2秒、平台继续/停车、干净观测/噪声及±5°初始偏航和±0.1m侧向偏移。全部使用ONNX实际驱动仿真，并逐步与原检查点学生输出比较。平台采用专用封顶几何，外侧阶数少于原始整块楼梯；原始楼梯4米测试结果另记于报告，不能混成一种通过率。固定测试矩阵不等于真实环境随机成功率。
